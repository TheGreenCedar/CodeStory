# Packet generalization

Packet compilation is repository-derived. The original question may seed
generic lexical and semantic retrieval, but no part of its wording has exact
selector authority. Repository paths, canonical IDs, and qualified symbols
enter only through typed probes. Typed free-query probes remain ordinary
generic retrieval seeds. Once retrieval returns candidate descriptors, neither
the question nor any prompt-derived policy crosses the compiler boundary.

## Required sequence

```text
question + typed probes
  -> RetrievalSeedPlanV1
  -> descriptor-only retrieval
  -> packet-wide admission
  -> admitted source and relation hydration
  -> PacketCompilationInputV1
  -> repository-derived selection
  -> 16-row / 16-KiB public projection
```

Exact typed selectors are copied without interpreting the question, resolved
through identity indexes, and admitted first.
Every remaining feasible unique identity is attempted in versioned retrieval
rank. Optional publication-bound call hints cannot evict a higher-ranked eligible
identity. Unaffordable source bounds are refused without refunds; later feasible
identities continue in rank. One
packet-scoped session admits at most sixteen stable identities and reserves at
most 16 KiB of conservative source bounds before any candidate source, graph
neighbourhood, node body, or file record is loaded. Initial retrieval, typed
probes, batches, and continuations share that session.

Initial descriptor pages reserve at most 512 source bytes each. Once descriptor
admission is sealed, runtime first shares spare source capacity fairly across
already admitted nodes with publication-authenticated requested source ranges,
then fairly across context nodes, up to 4 KiB each, before reading any body.
Both initial pages and authenticated typed continuation pages use this same
charged allocation. This does not add identities, refund earlier reservations, change
retrieval ranking, or inspect the question. Source bounds, complete-line paging,
publication checks, the single continuation round, and the complete 16-KiB
serialized public projection remain enforced. If spare capacity is insufficient,
the page stays bounded and reports its remaining source bytes.

Every observed coverage gap remains explicit in the measured public response,
whether response-size selection retains or omits its bounded source witness.
A verified source page permits positive evidence without establishing complete
index coverage. A continued packet may retain the exact
publication-authenticated page it delivered under that gap, without offering
another round or asserting answer sufficiency. Parent IDs alone, an omitted
requested page, stale publications, and other coverage failures cannot use
this exception.
The page binding uses the original authenticated hydration witness, including
its full delivery receipt and physical bounds. Symbol resolution stays identity-only;
any optional descriptor path constrains the independently verified source path.

For every admitted node page, the same verified source read also prepares smaller
complete-line pages at normalized smaller caps of 2048, 1024 and 512 bytes. Runtime measures
those private witnesses with the actual caller envelope before freezing delivery.
Row pruning cannot discard the requested page while a smaller extent is pending.
The selected page keeps the same publication, file hash and requested bounds, with
its physical end, unread bytes and next-line cursor recomputed from the verified
content. No additional source read, admission, reservation refund, retrieval or
continuation round occurs. At most seven extents each have fifty-one row
proposals: the original,
three globally smaller extents, and three extents that keep requested pages
while shrinking context. When an authenticated served-source record exists,
the smaller-request family restores each unrequested issued prefix and its receipt;
it does not shorten protected old bodies together with the new requested page.
Requested protected rows remain subject to the unchanged prefix guard. The actual
authenticated cursor is saved before restoring old ranges; requested selection
must deliver at least that first requested line. An unchanged prefix is still
measurable as the protected floor, with an explicit refusal if progress cannot fit.
The existing verified-cost read can derive the smallest complete-line extension
with the full original requested range. A shrink page that stops before the cursor
is replaced only when independent fresh hydration covers the same prefix, hash
and range within its actual reservation. Remaining bytes and cursor still describe
the full original range. This replaces an existing family and does not increase
the extent, callback or source-read bound.
Duplicate extents are measured only once. An additional
fifty-one proposals can measure an explicit refusal after no extent fits. A
chosen fitting extent is remeasured once through the actual caller
before freezing so the caller's accepted packet matches the winning source
extent and authenticated navigation paths. That final measurement refuses
changed size, cancellation or errors. Existing per-proposal latency and
cancellation checks remain in force.

The default pure compilation reserves one graph witness row when space permits.
Measured selection also considers a source-first allocation at each row limit,
alongside that graph-preserving allocation, using only the same admitted and
hydrated evidence. A third allocation keeps authenticated typed selectors in admission order.
When admitted publication-bound call hints reach a hydrated source, it orders
complementary targets by marginal incoming-seed coverage; otherwise it retains
the complete-first ordering of complete physical pages before incomplete pages, using serialized source-row size and original admission ordinal to break
ties. It competes through the same full caller-envelope measurement; cheaper
complete context may be unrelated to the question. The graph-preserving and source-first allocations
remain available and all omitted source ranges retain honest continuation. Duplicate allocations are measured once. When both fit,
complete source bodies, retained source rows and rendered source bytes select
the family; ties keep the graph witness. Every omitted relation preserves its
structural selectors even when its endpoint bodies are delivered. No relation
completeness or answer sufficiency is inferred. Runtime compares measured
complete-line extents by completion and delivered bytes of explicitly requested
source ranges,
then complete source bodies, retained source identities and delivered bytes.
Complete means physical source delivery, not behavioral
coverage or answer sufficiency.

Public retained source tails and the broad continuation expose an executable
`packet_request_patch`. Replace all five continuation fields on the original
packet request, retaining its question, budget, latency and caller's project,
profile, run and cache context. Empty arrays and nulls explicitly clear prior
probes, parent and options. CLI callers replace corresponding flags rather than
appending them. Source actions contain either one existing typed Continuation probe or one
canonical compact numeric range option decoded to that same probe. Both retain
the exact next line, requested end, node identity and publication pins. Compact
source actions bind their parent to the current execution request and retain
strict cursor validation; they do not establish stored parent-offer membership.
They remain ordinary bounded packet operations which may perform retrieval;
they do not offer another broad compiler round. Unpageable physical lines report
the honest bounded refusal instead of an action that cannot make progress.
The action bytes participate in immutable-record validation and complete public
serialization measurement.

Continuation option IDs are opaque references, never access capabilities. The
contracts codec emits `ms1:<start>:<end>:<signed-node>` only for canonical numeric
node ranges and accepts both that version and canonical legacy percent-encoded
IDs. Other selectors retain their legacy spelling. Clients echo the returned ID;
raw incoming IDs remain in request fingerprints. Decoding preserves selector
semantics and does not bypass project, publication, node or source-range checks.
The current incoming packet path checks parent presence, not membership in a
stored parent offer; this codec adds no parent authorization or expiry claim.

The compiler receives admitted identities, hydrated source ranges, certain
directed relations, parser completeness, ambiguity, and one pinned publication
identity. It may prefer distinct paths, remove contained source ranges, retain
a bounded connecting forest, add one certain incident relation for a
disconnected seed, prefer source witnesses over symbol-only locations, and
apply deterministic byte costs. It cannot receive the raw question.

## Forbidden production shapes

- Prompt or task-class classifiers, including renamed or encoded variants
- Domain, lifecycle, relation-language, or expected-answer taxonomies
- Fixed answer stages, claim obligations, carrier classes, or magic evidence
  roles
- Prompt-word rescoring after generic retrieval
- Synthesized claims or benchmark-shaped result deletion passes
- Basename-only path identity
- Diagnostic prose reused as a continuation query
- Production dependencies on benchmark manifests or expected answers
- Sufficiency, absence, runtime-execution, or complete-coverage assertions
  inferred from retained or missing evidence

Typed `FreeQuery` probes are ordinary additional generic retrieval queries.
They receive no rank protection, materiality, or sufficiency authority. A
continuation carries stable selectors, publication pins, and the exact typed
structural reason it was offered. It does not claim that the current packet is
insufficient for the answer.

Historical 18-task, Q2, Dart, and 45/54 results are contaminated development
evidence only. They cannot authorize a product or release claim.

## Boundary checker

CI runs:

- `node scripts/lint-retrieval-generalization.mjs`
- `node scripts/check-packet-generalization-boundary.mjs`
- their hostile Node test suites

The packet boundary checker fails closed when no production files are scanned,
masks only real test-only regions, and rejects semantic equivalents of the
forbidden shapes rather than a list of retired identifiers. Vocabulary naming
those shapes is permitted only in tests, tooling, and checker fixtures.

## Public claim

The public packet reports bounded source and indexed structural evidence,
typed gaps, ambiguity, truncation, and its pinned publication identity. It
always reports `answer_sufficiency: not_asserted`.

Published call metadata is optional navigation data. The normal descriptor
executor joins at most sixteen eligible ranked symbol identities against the
same immutable lexical component envelope, without FTS, content decoding, Core
queries or source hydration. Delta ownership and tombstones precede lookup; old
metadata-free schemas and cold/missing validation receipts retain rank fallback.
This optional lookup never invokes a deep-validation fallback. The joined annotations enter the
publication-keyed descriptor cache. Admission protects exact/issued identities
and then attempts the full feasible unique retrieval-rank prefix. Metadata
validation, deduplication and sticky conflicts remain independent of admission
rank. A separate full-pool pass retains annotations for already-admitted owners
even after the new-identity count limit is reached. Lower-ranked callees may lose
admission; retained hints do not guarantee their continuation.
Truncated neighborhoods may contribute owner-validated positive hints but never
assert complete adjacency or absence. Uncertain annotations guide navigation without becoming certain
relationship evidence. Symbol names, paths, languages, question obligations and
test/production roles do not enter this ordering.

After admission, runtime carries only owner/publication-validated call hints
whose endpoints are admitted into private source-selection metadata. The pure
compiler uses reciprocal admission rank to cover complementary source targets
in one measured ordering. It never emits these hints as certain graph evidence;
normal induced certain relations remain separately hydrated and projected.
No new row family or measurement bound is added. Metadata-free input retains
the earlier physical-completion alternative. Exact requested source priorities,
source extents, gaps, navigation and full-frame measurement remain unchanged.

The normal CLI can issue an immutable served-source record after its complete public envelope is finalized and rendered. Runtime stores bounded metadata only: actual transport caller, execution request, project and Core/retrieval publication identities, question digest, exact delivered bounds/receipt, rendered reservation and source-prefix digest. An owner-private HMAC key authenticates issuance across CLI processes. The record has a one-hour lease, immutable idempotent commits, bounded inventory scanning and 128-MiB scope/512-MiB namespace limits; expiration never evicts or renews evidence automatically. Preview/projector callbacks and BudgetExceeded results never issue history. This is ordinary local-file integrity, not same-user agent or native credential isolation.

A marked numeric source-page continuation must resolve its real issued record under the same transport/question/publication; missing, foreign, expired or tampered history refuses. Runtime reserves all protected identities/bytes before optional descriptor retrieval, rehydrates the original delivered prefix from sealed current source, and freezes every prior body/receipt/citation before new optional context competes. Both actual public projection and adapter-final commit verify all prior prefixes. The original cap and whole-chain latency contract remain unchanged. Legacy FILE/path sources without paging receipts and stdio retain their existing conservative path and identifiers; this CLI implementation does not claim their historical receipt qualification.

The owned packet operation's existing private diagnostic log records at most four
query views with sixteen eligible identity digests, returned ranks and exact fused
score bits each, plus at most sixteen call-target ordering promotions. Promotion
masks refer to the aggregate ranked seed prefix and distinguish total from
uncovered seeds. This content-free observation performs no query, body read or
admission and changes no ranking, public response or budget. Missing views or
rows remain unobserved; these records cannot prove answer coverage. Stage codes
1 and 2 distinguish view rows from promotions while retaining the existing safe
digest-list redaction rule. Nested/non-packet operations cannot contribute. Views and ordering promotions are
frozen to their first observed attempt; later retries cannot append masks against
a stale ranked prefix. Numeric attempt ordinals allow joins to the retained RAF
ranked observation. Ordering promotions do not prove successful admission.

Admission rank protection does not guarantee public source retention or answer
coverage. Source-row selection remains a separate measured allocation over
admitted evidence; below-cutoff identities remain absent unless independently
admitted through supported selectors.

The additive joint stage accepts a partial callable page only when verified body
metadata intersects its delivered physical lines. It preserves every baseline
source/graph row, subtracts their physical coverage as a union, and ranks positive
new body lines before complete-unit ties. Aliases and overlapping pages cannot
multiply progress; headers, unknown/conflicted metadata and already-covered
pages earn none. Single/pair proposal and caller-renderer bounds are unchanged.
Incomplete additions keep authenticated requested extents, hashes, raw remaining
bytes and supported source cursors; they never assert body completeness.

Joint addition considers the verified page frontier after baseline selection.
Each trial restores every baseline source from its exact hydrated witness,
including parser/body metadata, physical bytes and delivery receipt; baseline source and
graph rows remain unchanged. Both variants of each verified cap collapse after
restoring requested/issued baseline rows. At most four distinct mixed inputs
(original plus three caps) compete through the existing single/pair search.
Canonical baseline support and continuation must match for each input; invalid
mixed inputs earn no candidate. New physical body lines and complete-unit ties
are compared across all fitting trials, followed by final validation with the
winning input. No source is read or admitted again. At most eight baseline
families of fifty-one proposals, four joint searches of 139 callbacks, and one
final validation use 965 callbacks, within the unchanged 1049 whole-request guard.
Unsupported mixed inventories fail closed; source/count/wire limits stay fixed.

An additive partial source page never resolves an original full-range action.
If the canonical compiler frontier replaces that action with a tail, runtime
requires the exact authenticated source row, original requested range, contiguous
prefix and matching canonical tail before restoring the original action verbatim.
Publication, parent, limits, labels and gap identity stay unchanged. The partial
row separately exports its next-page action; the original action remains valid.
Both actions and every old source row pass the unchanged final public-frame
guard and serialized byte measurement. No new admission or source read occurs.
